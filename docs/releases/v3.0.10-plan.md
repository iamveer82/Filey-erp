## Draft verification and publishing

The release workflow builds Windows, Linux, macOS ARM and macOS Intel in sequence,
runs native security/storage tests and creates a draft. Its final asset check is
necessary but is not cryptographic verification.

Before publishing, require Windows EXE/MSI, Linux DEB/RPM, both macOS DMGs, both
macOS app.tar.gz updater archives, their updater signatures and latest.json.
Download the actual draft assets; verify GitHub SHA-256 digests, embedded version
and architecture, all manifest URLs and signatures against the unchanged public
key. Reject any missing or mismatched platform. Remove the generic Linux target
when no compatible AppImage exists, preserving the explicit DEB/RPM targets so
older AppImage clients cannot install DEB bytes over their executable.

Publish the complete draft as latest, then read the public updater endpoint and
confirm version 3.0.10, matching platform URLs/signatures and accessible downloads.
Keep the previously stopped release automation stopped.

macOS remains without Apple notarization and Windows without Authenticode signing;
these are existing distribution limits, separate from required updater signatures.
