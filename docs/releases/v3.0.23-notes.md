# Filey ERP 3.0.23

Invoices reuse current company and customer electronic identities across manual drafts, AI, scanning and quotation conversion. Older drafts can fill missing seller details without changing manual entries or issued invoices. Customer and supplier presets preserve optional fields and deliberate clearing. UAE fields remain optional for ordinary drafts, while the free XML checker validates the requirements for structured export. Filey's UUID is labelled as a preparation identifier; accredited submission still requires an ASP.

Hosted chat drafts use the same document numbering sequence as the app. T.Liters pricing retains the supplied physical quantity, unit and rate, and uses the selected custom column for calculation. Seller and uniquely matched customer presets are retained. Unsupported calculation overrides stop before saving rather than silently changing the invoice.

Scans preserve zero quantities and units, reject invalid model output and oversized documents, and cancel when the dialog or workspace changes. PDFs exceeding the eight-page scan limit produce an explicit message rather than silently losing later pages. Retrying an uncertain scan save retains its exact request and invoice number. Supplier XML imports preserve original AED exchange rates and supplier identities.

Delayed profile responses cannot replace another signed-in account's profile. Legacy cloud sync keeps failed or conflicting queued edits instead of discarding them; Settings shows pending counts and a retry action. Slow invoice editor loads cannot overwrite newer edits.

Update through Filey's normal updater; uninstalling is not required. Existing local documents and data directories are preserved. Self-hosted cloud deployments must apply `supabase/2026-10-08-hosted-draft-parity.sql` after prior migrations before updating `channel-webhook`. The migration changes functions only and does not renumber existing documents. Fresh schema setup includes the same changes. No new dependency is added.
