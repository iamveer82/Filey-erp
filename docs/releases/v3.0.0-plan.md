# Version 3.0.0 release checklist

## Prepared

- App, npm lockfile and Tauri/Rust versions are 3.0.0.
- Release notes: [v3.0.0.md](./v3.0.0.md).
- The top invoice Preview uses a full-screen mobile viewer, fixed A4 layout and reading zoom. Quotes, purchase orders and receipts share the same dialog treatment.
- Prior account, Devices, billing and AI changes remain included in PR #10.

## Build and publish

1. Wait for CI and Vercel preview checks on the final commit. Review the mobile Preview at phone and landscape widths; physical iPhone Safari remains a separate device check.
2. Merge PR #10 after checks pass. Confirm the production web deployment so iPhone users receive the same preview fix.
3. Create a new `v3.0.0` tag at the merged commit and push it. Do not reuse the older `v2.12.0` draft/tag; it predates the latest fixes.
4. Let `release build` package Windows x64, Linux DEB/RPM, and both macOS architectures. The workflow creates a draft and verifies all platform installers are present.
5. Inspect `latest.json`: version 3.0.0, matching v3.0.0 download URLs, and nonempty updater signatures for Windows and both macOS architectures. Verify each referenced artifact exists. Linux updates remain manual.
6. Install the Windows build on a test profile and check upgrade/startup, Settings → Devices and invoice Preview without editing customer records. Confirm the existing updater public key is unchanged.
7. Apply the release notes, publish the verified draft as the latest release, and read the public `/releases/latest/download/latest.json` endpoint to confirm existing desktop installs receive 3.0.0. Verify the production web app separately.

## Service limits to retain in release notes

BYOK image/video generation needs the customer's provider credentials and balance. Shared AI wallet providers and credit checkout are not claimed active until merchant/provider setup is completed. Do not bundle credentials or enable unconfigured paid services as part of publishing.

## Recovery

Keep the previous published release available. If a critical issue appears, stop promoting the new release and ship a forward patch version with verified updater artifacts; never overwrite the signed 3.0.0 assets or reuse its tag. Avoid reverting database migrations or customer records to roll back a UI release.
