# Filey ERP 3.0.15

This patch fixes a local-to-cloud transfer that stopped when older workspace
records and company-setting conflicts needed recovery together. The existing
cloud checks still require both workspaces to belong to the same owner and
the old workspace to have no active users. Other access failures remain blocked.

Transfer failures now explain schema or access problems without exposing record
contents or database errors. Device mode stays open until the transfer finishes.

This release also includes the document, inventory, AI connection, profile mascot
and workspace file-transfer improvements prepared for the unpublished 3.0.14
release. See the [3.0.14 change notes](v3.0.14-notes.md) for those details.

No new runtime dependency or cloud migration is required. Local records stay on
the device unless the user chooses and confirms a cloud transfer.
